VPN Guard for Windows 0.2.0-preview — защита рабочей сессии

Это отдельная Windows-версия. Она использует Windows Filtering Platform
для прямых соединений выбранных ChatGPT/Codex, Claude и нативных CLI.
Конфиг VPN, ключи и IP сервера в программу не входят.

ТРЕБОВАНИЯ
Windows 10/11 x64, Windows PowerShell 5.1 и штатный компилятор .NET Framework.
PowerShell 7 и ARM64 не поддерживаются. Для установки нужен администратор;
начало и завершение сессии из окна работают без UAC.
VPN-клиент — Amnezia XRay/VLESS в режиме TUN: адаптер tun2 с описанием
tun2socks Tunnel, в том числе с суффиксом « #2». Другие клиенты, AmneziaWG,
системный proxy-only и произвольные адаптеры автоматически не доверяются.

Найденные приложения могут быть установлены через MSIX/Store (OpenAI.Codex,
OpenAI.ChatGPT, Claude). Нативный Claude Code ищется в .local\bin и npm-пакете
@anthropic-ai\claude-code; Codex — в AppData\Local\OpenAI\Codex\bin и нативных
vendor-каталогах npm-пакетов @openai\codex / @openai\codex-win32-x64.
Нужен хотя бы один поддерживаемый EXE. Другие способы установки не охвачены.

УСТАНОВКА
Распакуйте Windows-архив или откройте папку windows в исходниках.
Запустите Install.cmd. Он собирает DLL из включённого WfpGuard.cs без
скачивания зависимостей, затем показывает запрос администратора Windows.
VPN может быть отключён. Установщик проверяет профиль выбранного пользователя
и найденные приложения, размещает код в Program Files\VpnGuard с доступом
записи только у SYSTEM и администраторов, создаёт две задачи и ярлык.
Успех означает свежий статус сторожа, а не проверку конкретного VPN на утечки.

Установщик не перезаписывает другую или неизвестную существующую версию.
Не удаляйте рабочую установку ради эксперимента. Обновление старой preview
нужно делать отдельно после сохранения работы: штатным удалением старой
версии, перезагрузкой и удалением оставшейся папки Program Files\VpnGuard
с правами администратора; только затем возможна чистая установка этой версии.
Повторный Install.cmd той же версии восстанавливает задачи после Remove.cmd.

КАК РАБОТАЕТ СЕССИЯ
1. После новой загрузки Windows — ожидание Amnezia. Фильтров VPN Guard нет,
   обычный интернет выбранных приложений разрешён. Это не always-on lockdown.
2. Подключение доверенного адаптера автоматически начинает сессию.
3. Во время сессии разрешены туннель Amnezia и localhost; прямой внешний
   выход выбранных процессов запрещён для IPv4/IPv6.
4. Если туннель исчезнет, сессия остаётся активной и прямой выход блокируется.
   Новый GUID tun2 распознаётся; доступ через VPN восстанавливается.
5. Перед ручным отключением нажмите «Завершить сессию» в окне или End.cmd.
   Правила снимаются. Если VPN уже отключён, команда тоже снимает блокировку.
6. При том же подключении «Начать сессию» / Begin.cmd возвращает защиту.
   После отключения и нового подключения она включается автоматически.

Закрытие значка не завершает сессию. Обычный перезапуск сторожа сохраняет
режим в пределах той же загрузки Windows. Статические WFP-объекты переживают
закрытие управляющего процесса, но не перезапуск Windows/BFE. Состояние новой
загрузки определяется заново. Перезапуск BFE во время сессии отдельно не
покрыт. Включение сессии и новые пути обнаруживаются опросом, не мгновенно.

УПРАВЛЕНИЕ
Open.cmd / ярлык — окно со статусом, кнопками начала и завершения сессии.
Status.cmd — статус без окна. Begin.cmd / End.cmd — команды без UAC.
Remove.cmd — с правами администратора останавливает и удаляет обе задачи,
снимает только собственные WFP-фильтры. Файлы и ярлык остаются для восстановления.
Удаление распакованного ZIP и закрытие значка не снимают активные правила.
Старые команды Apply и Lock в Control.ps1 — совместимые псевдонимы Begin;
отдельного ручного запрета всего VPN-трафика в этой версии нет.

ПРОВЕРКА НА СВОЁМ КОМПЬЮТЕРЕ
Сначала сохраните работу. В ожидании без VPN проверьте Mode=Waiting и 0 правил.
Подключите Amnezia, дождитесь Mode=Armed и подтверждённых правил. Отключите
VPN без завершения сессии: новые прямые соединения приложения должны блокироваться.
Переподключитесь, затем завершите сессию кнопкой и проверьте снятие правил.
Проверьте повторно после перезагрузки. Эти наблюдения не доказывают отсутствие
утечки уже открытых соединений или покрытия всех протоколов и дочерних процессов.

SelfTest.ps1 проверяет синтаксис, структуру DLL, состояния сессии, обнаружение
приложений на фиктивном профиле и права локальных событий. Он не запускает
установщик, не посылает команды настоящему сторожу и не меняет сетевые правила.
Команды разработки:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\SelfTest.ps1

ОГРАНИЧЕНИЯ
DNS через общую службу Windows, локальные прокси, WSL/виртуальные машины,
отдельные дочерние команды и MCP-серверы находятся вне выборочных фильтров.
Новый EXE при обновлении может успеть подключиться до обнаружения (до 15 секунд
между проверками путей). Ранний старт и новые сессии тоже имеют задержку опроса.
Уже открытые соединения, сон и конкретные версии VPN требуют отдельной проверки.
Наличие tun2 не подтверждает страну или репутацию внешнего IP. Геолокация
не проверяется, телеметрии и внешних IP-сервисов у Windows-сторожа нет.
При ошибке обнаружения старые фильтры остаются, но новые пути могут не покрываться.
Статус «сторож не отвечает» или «правила не подтверждены» требует проверки.

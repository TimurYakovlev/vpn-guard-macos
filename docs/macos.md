# VPN Guard for macOS — experimental

Открытый **дополнительный сторож** для Claude, ChatGPT, Codex и нативных CLI.
После входа в macOS он ждёт подключения доверенного VPN. Когда маршрут и
внешний IP подтверждены, начинается рабочая сессия. При обрыве сторож
приостанавливает выбранные процессы (`SIGSTOP`), а после восстановления VPN
возобновляет их (`SIGCONT`).

**Это не сетевой firewall и не гарантия отсутствия утечек.** Сторож обнаруживает
проблему после её возникновения. Между обрывом и остановкой приложения трафик
может уйти напрямую. Уже работающие сетевые службы, открытые соединения и
процессы, которые не удалось обнаружить/приостановить, могут продолжить работу.
Защита не равнозначна версии для Windows с WFP-фильтрами в активной сессии.

Основная защита — штатный kill switch VPN-клиента. У Amnezia он доступен в
настройках: **шестерёнка → Connection → KillSwitch**. По документации Amnezia,
при ручном отключении VPN он может разрешать обычный интернет. Этот сторож
дополняет его проверкой доверенного IP и маршрута, но также имеет задержку.
[Документация Amnezia](https://docs.amnezia.org/documentation/instructions/killswitch/).

## Требования

- macOS на Apple Silicon или Intel; целевая среда — macOS 14 и новее.
- **Python 3.10+**, установленный самостоятельно: [установщик Python для macOS](https://www.python.org/downloads/macos/)
  или `brew install python` при уже установленном Homebrew. Python не входит
  в раздачу; pip-пакеты не нужны. Само наличие macOS не гарантирует наличие Python.
- Полный VPN-туннель `utunN`, через который идёт IPv4 и имеющийся IPv6.
  Proxy-only и split tunneling не поддерживаются. Постоянный/стабильный внешний
  IP своего VPN; при смене IP требуется новая настройка с явным подтверждением.
- Приложения и сторож работают от одного обычного пользователя. Без `sudo`.

## Установка

1. Подключите свой VPN и включите его штатный kill switch. Закройте приложения,
   которые собираетесь защищать, предварительно сохранив работу.
2. Скачайте **Code → Download ZIP** и распакуйте. Либо клонируйте репозиторий.
3. Откройте Terminal в распакованной папке и выполните:

   ```sh
   sh control.sh install
   ```

   При клонировании Git можно также открыть `install.command` двойным щелчком.
   Если Finder не разрешает запуск, используйте указанную команду в Terminal;
   отключать Gatekeeper или SIP не требуется.
4. Настройщик покажет VPN-интерфейс и внешние IP. Проверьте, что подключён ваш
   нужный сервер; только затем подтвердите `TRUST`. **Не доверяйте адресу
   автоматически, если сомневаетесь, какое подключение сейчас активно.**
5. Проверьте список путей. Автоматически ищутся установленные `Claude.app`,
   `ChatGPT.app`, `Codex.app` в `/Applications` и `~/Applications`, а также
   найденные через PATH нативные Mach-O `claude` и `codex`. Можно добавить
   полный путь к другой установленной `.app` или нативному EXE вручную.
   Shell/Node.js-обёртки CLI не распознаются как нативные процессы: нужен путь
   к реальному Mach-O-файлу. Не добавляйте Terminal, shell, Python или VPN-клиент.
6. Подтвердите `SAVE`. Устанавливается пользовательский LaunchAgent, который
   запускается при входе в аккаунт и перезапускается после сбоя.
7. Выполните `sh control.sh status`. При подключённом настроенном VPN должны
   появиться `mode: active`, `healthy: true` и `heartbeat_fresh: true`.
   `mode: waiting` означает, что сторож запущен и ждёт доверенный VPN.

Если IPv6 выходит мимо VPN, настройщик откажется продолжать. Настройте полный
туннель средствами своего клиента; программа не отключает IPv6 глобально.
Если IP изменится во время работы, сторож приостановит приложения, пока
доверенный IP не вернётся или вы явно не завершите сессию.

Чтобы перейти со старой версии, выполните `sh control.sh uninstall`, затем
`sh control.sh install` из обновлённой папки с подключённым VPN. Удаление
освобождает процессы перед заменой LaunchAgent.

## Проверка на своём Mac

Только после сохранения работы:

1. При входе в macOS без VPN убедитесь, что режим `waiting` и выбранное
   приложение свободно работает.
2. Подключите доверенный VPN, дождитесь режима `active` и отключите VPN без
   завершения сессии: приложение должно приостановиться. В Activity Monitor его
   могут обозначить как «не отвечает» — это ожидаемо при `SIGSTOP`.
3. Подключите тот же VPN с доверенным IP: приложение должно продолжить работу.
4. Выполните `sh control.sh end`, дождитесь подтверждения и отключите VPN.
   Приложение должно продолжить работу.

Тесты GitHub проверяют логику, запуск и удаление LaunchAgent в изолированном HOME,
остановку/возобновление только собственного тестового процесса на Mac-раннере.
Они **не** подтверждают совместимость
конкретного VPN, защиту реальных приложений или отсутствие утечки при обрыве.
До этих ручных проверок считайте установку непроверенной на своём устройстве.

## Управление и восстановление

```sh
sh control.sh status
sh control.sh end
sh control.sh begin
sh control.sh uninstall
```

Перед ручным отключением VPN выполните `end` или откройте `end.command`.
Команда завершает сессию и возобновляет приостановленные сторожем процессы,
даже если VPN уже успел отключиться. Сторож автоматически начнёт следующую
сессию после отключения и нового подключения. `begin` возвращает защиту при
том же подключении, как только маршрут и IP подтверждены.

При обрыве активная сессия сохраняется и при перезапуске самого сторожа.
Новая загрузка macOS начинает ожидание доверенного VPN.

`uninstall` снимает пользовательский LaunchAgent и возобновляет только процессы,
которые сторож записал как приостановленные им и которые всё ещё совпадают по
PID, пользователю, времени запуска и пути. Программа не завершает приложения
и не отключает сетевые правила VPN. Конфиг сохраняется локально.

Для изменения IP/путей: сначала `uninstall`, затем `install` заново. Учтите,
что после удаления сторожа дополнительной защиты от него нет.

Если установка прервалась, сохраните ошибку. Проверить агент:

```sh
launchctl print gui/$(id -u)/org.vpnguard.macos.watcher
```

Если требуется аварийно отключить сторож и разморозить записанные им процессы:

```sh
launchctl bootout gui/$(id -u)/org.vpnguard.macos.watcher
sh control.sh resume
```

`bootout` может сообщить, что агент уже не загружен. `resume` откажется работать,
пока работающий экземпляр держит блокировку. Возобновление не включает защиту.
При утрате локального `paused.json` автоматическое восстановление невозможно;
сохраните работу и используйте Activity Monitor/перезапуск нужного приложения.

## Ограничения

- Опрос процессов — примерно каждые 0,5 секунды, отдельно идут сетевые проверки.
  HTTPS, таймауты, нагрузка и планировщик добавляют задержку. Это могут быть
  секунды (и больше при зависании/сне), а не гарантированные миллисекунды.
- Работа не начинается до пользовательского входа и старта LaunchAgent.
  Завершение/зависание самого сторожа не устанавливает сетевую блокировку.
- Новый процесс может успеть подключиться до обнаружения. Потомки отслеживаются
  по текущему дереву процессов; быстрые, уже переподчинённые и системные процессы
  могут остаться вне охвата. Отдельно запущенные CLI требуют собственного пути.
- Общие DNS-службы macOS, локальные прокси, системные сетевые процессы,
  виртуальные машины, другие пользователи не изолируются.
- Идентификация PID повторно проверяется перед сигналом, однако между проверкой
  и сигналом остаётся системная гонка; время старта от `ps` имеет точность до секунды.
- Не добавляйте программы, которые держат критичные транзакции/блокировки:
  приостановка всего приложения способна мешать другим локальным инструментам.
- IP и `utun` подтверждают маршрут проверочных запросов, а не все возможные
  маршруты каждого приложения; геолокация и репутация VPN не проверяются.
- Публичные IP должны быть стабильны. На балансируемых/общедоступных VPN
  возможны ложные остановки. Несколько VPN одновременно не поддерживаются.
- Это самостоятельный открытый код, не официальный продукт Amnezia, Apple,
  Anthropic или OpenAI; исходники Kordon здесь не используются.

## Приватность и локальные файлы

Конфигурация, доверенные IP, PID/пути приостановленных процессов и состояние сессии
создаются **только на Mac пользователя**, в `~/Library/Application Support/VPN Guard`.
Папка получает права `0700`, JSON — `0600`. LaunchAgent:
`~/Library/LaunchAgents/org.vpnguard.macos.watcher.plist`.
Публичный репозиторий не содержит VPN-профилей, ключей, IP автора, Telegram-сессий
или переписки. Не загружайте свои локальные JSON в issues или коммиты.

Проверка внешнего IPv4 использует `https://api.ipify.org`, IPv6 —
`https://api6.ipify.org`. Эти внешние сервисы видят адрес исходящего VPN-соединения
и время запросов. Содержимое приложений не читается и не отправляется.
Нет Telegram-бота, аналитики, удалённого управления или собственного сервера.
Запросы обходят прокси и привязываются к проверяемому VPN-интерфейсу.

## Разработка

```sh
python3 -m unittest discover -s tests -v
```

Две дополнительные интеграционные проверки выполняются только на macOS;
на других ОС сигналы симулируются. CI использует Apple Silicon и Intel Mac.
Python стандартной библиотеки, без runtime-зависимостей из pip.
